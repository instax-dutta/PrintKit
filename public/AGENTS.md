# public - PWA assets

## Purpose

Everything served verbatim at the site root: service worker, manifest, and icons. This folder is what makes the app installable and offline-capable.

## Ownership

- `sw.js` - hand-written runtime cache (cache-first for same-origin GETs after first visit; skipWaiting message protocol)
- `manifest.webmanifest` - name, theme colors, and 192/512 icon entries (any + maskable)
- `icon.svg` - source icon
- `icon-180.png`, `icon-192.png`, `icon-512.png` - generated by `scripts/genIcons.mjs` equivalent (`scripts/gen-icons.mjs`, zero-dependency Node PNG writer); run `npm run icons` to regenerate

## Local Contracts

- `sw.js` ships a `printkit-v1` placeholder that the `stamp-service-worker` plugin in `vite.config.ts` replaces with a fresh version in `dist/sw.js` on every build; clients update via skipWaiting + in-app banner, and `activate` deletes the previous cache.
- Manifest icon paths and sizes must match the generated PNG names exactly; a mismatch breaks installability.
- Do not vendor binary assets here; icons regenerate from `icon.svg`.

## Work Guidance

- Keep the `printkit-v1` string in `public/sw.js` as the placeholder the build substitutes; changing its wording silently disables version stamping.
- Keep the manifest lean: `GATES.md` G2 checks these assets exist in `dist/` after build.

## Verification

- `npm run build && ls dist` - Vite copies these files verbatim to `dist/`; G2's checker looks at the dist root, not `dist/assets`.
- Installability end-to-end is `GATES.md` M2 (deploy + Lighthouse PWA check) and remains a manual gate.
